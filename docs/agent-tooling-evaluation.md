# Agent and developer-tooling assessment

**Review date:** 20 October 2026. This is an engineering fit assessment for this repository, not a blanket security audit or a claim that every upstream benchmark is independently reproduced.

## Architectural baseline

The repository contains a static HTML/JavaScript mobile app and an optional Python FastAPI gateway beside Ollama. The target production host is constrained to 8 GB RAM. The gateway must stay small, compatible with /v1/chat/completions, and private except through its authenticated HTTPS ingress. Developer-agent tooling belongs on a developer/CI runner, not on the inference VPS.

## Chosen implementation

1. Add a root AGENTS.md with architecture invariants, a bounded Harness²-inspired Propose–Probe–Compose workflow, reviewer independence requirements, and evidence-gated learning rules.
2. Add portable skills for verified agent work and cache-gateway maintenance.
3. Strengthen the gateway's streaming behavior, route-specific cache keys, bypass rules and deployment defaults.
4. Keep all agents, skills, benchmark harnesses, and optional developer tools outside the production inference path.

## Needle evaluation gate

Before trying the small Needle tool router, assemble a versioned set of at least 100 representative requests: tool selection, malformed/ambiguous requests, no-tool requests, security-sensitive requests, and Russian-language inputs. Compare (a) deterministic routing, (b) Needle proposal + deterministic schema validation, and (c) current model routing. Measure exact tool-set accuracy, false dispatch, abstention, latency and memory. A nontrivial false-dispatch rate blocks autonomous use. The model may propose bounded actions; deterministic code must validate them, and the main model/human remains the fallback.

## What is not claimed

No upstream benchmark has been rerun as part of this repository change. No package or third-party plugin is installed onto the Vultr server. No change has been made to live Cloudflare routing. Agent tools are not trusted just because their repository is popular or open source.
